Developer detail: two connections, different jobs

The host talks to the MCP server using MCP transport, such as Streamable HTTP. The embedded UI talks to the host through the MCP Apps bridge using messages. The host mediates tool calls; UI code does not receive a universal pass to your backend.

07 · A real customer, a new connection

“It’s me” and
“I’m allowed”
are different checks.

01 / CONNECT

The host starts OAuth.

It discovers your authorization server and begins account linking.

02 / SIGN IN

Your identity provider.

The person authenticates and grants consent. Existing account identities can be reused.

03 / CALL

The host sends a token.

Authenticated MCP requests carry the access token. Keep credentials out of UI props.

04 / ENFORCE

Your server decides.

Validate the token, its audience and scopes, then check access to the requested organization and records.

For an existing SaaS: plan a proper OAuth connection for the integration. A browser’s website session and the plugin’s authorization are separate. A project deep link may still require website sign-in.
Implementation checklist, minus the OAuth rabbit hole

Use authorization code + PKCE, publish discovery metadata, register the correct resource/audience, and use the callback URI shown by the host. Check signature, issuer, expiry, scopes, and product permissions on the server. Treat model- and UI-supplied identifiers as untrusted inputs.

09 · The build recipe

One goal. One tool.
One useful screen.

For Launchpad: “Help me spot project issues, then open the web app for management.” Keep the first release easy to understand and test.

  1. Choose the outcome.What can the person finish here? Write the success condition before designing the card.
  2. Build the tool contract.Define list_projects, a clear description, input/output schemas, and truthful annotations.
  3. Connect existing business logic.Reuse project services; enforce permissions before retrieving data.
  4. Build and register the view.Compile React, register its UI resource, and connect it to the tool.
  5. Handle the unglamorous states.Loading, empty accounts, errors, expired auth, and stale data are part of the product.
// Descriptor excerpt — not a complete server
{
  name: "list_projects",
  description: "List project health for the connected workspace.",
  annotations: { readOnlyHint: true },
  _meta: {
    ui: {
      resourceUri: "ui://launchpad/projects-v1.html"
    }
  }
}

// Handler returns model-readable data as well
{
  structuredContent: {
    projects: [ /* authorized records */ ]
  }
}

Add schemas, authentication, transport, resource registration, and error handling using the current SDK docs. This is the relationship between the pieces, not copy-and-run scaffolding.

A useful tool should still work without its UI. The assistant can summarize project health from structured results. The view adds inspection and navigation.
10 · Before the launch confetti

Make it work
in the actual host.

Deploy = run your code

Your infrastructure.

Build the UI, include its resources with the server, and expose a stable HTTPS MCP endpoint for public distribution. A tunnel can support early testing.

  • Use a separate test environment and sample accounts.
  • Check tool calls directly with MCP Inspector.
  • Verify error handling, logs, and service availability.
Connect = try the experience

Inside ChatGPT.

Go to Plugins → plus → Add custom MCP server. Enter the endpoint or tunnel, configure authentication, then create and install the plugin. Account and workspace policies apply.

  • Start a new conversation and invoke the plugin.
  • Test both tool results and rendered UI.
  • Refresh the custom connection after metadata changes.

Our Launchpad test lap

Authorized projects only → status matches the web app → empty and expired-login states work → Refresh updates the view → a project link reaches the correct browser page.

Browser handoff is a first-class feature. Use the host’s supported link-opening API and required destination metadata. Test both signed-in and signed-out website sessions.

13 · Opportunity, with the fine print in normal-sized type

A listing is
a starting line.

Distribution

Findable ≠ featured.

Published plugins can be found by name or through their directory link. Featured placement and proactive suggestions are selective, not guaranteed.

  • Give people a concrete reason to connect.
  • Show a starter prompt that produces a useful result.
  • Our suggested metrics: connection success, task completion, and return use.
Monetization · checked 06 Oct 2026

Read today’s rules.

Current guidelines restrict plugin commerce to physical goods. They prohibit selling digital products or subscriptions and promoting upgrades.

People may sign in to an existing paid account and use already-included features. Don’t design your SaaS launch around an assumed in-plugin checkout.

A developer’s hypothesis: a useful integration may strengthen an existing product’s adoption and retention. That is something to measure—not a promise of installs, revenue, or marketplace payouts.
